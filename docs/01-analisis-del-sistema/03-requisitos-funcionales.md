# Requisitos Funcionales

## Sistema Integral de Gestión Turística de Huamanga

Los requisitos funcionales describen las operaciones que el sistema deberá ofrecer para satisfacer las necesidades de los visitantes, prestadores turísticos y administradores.

### RF01 — Consultar atractivos turísticos

El sistema deberá permitir al visitante consultar los atractivos turísticos publicados, mostrando la información disponible de cada uno.

**Historia relacionada:** HU01.

### RF02 — Buscar servicios turísticos

El sistema deberá permitir al visitante buscar servicios turísticos registrados y mostrar los resultados que coincidan con su búsqueda.

**Historia relacionada:** HU02.

### RF03 — Consultar eventos y festividades

El sistema deberá permitir al visitante consultar los eventos y festividades publicados, mostrando la información registrada.

**Historia relacionada:** HU03.

### RF04 — Consultar rutas turísticas

El sistema deberá permitir al visitante consultar las rutas turísticas publicadas y visualizar sus detalles disponibles.

**Historia relacionada:** HU04.

### RF05 — Visualizar información detallada de servicios

El sistema deberá permitir al visitante seleccionar un servicio turístico y consultar su información detallada.

**Historia relacionada:** HU05.

### RF06 — Registrar servicios turísticos

El sistema deberá permitir al prestador turístico autorizado registrar información de sus servicios, validando los campos obligatorios.

**Historia relacionada:** HU06.

### RF07 — Actualizar servicios turísticos

El sistema deberá permitir al prestador turístico autorizado actualizar la información de los servicios que tenga permiso para administrar.

**Historia relacionada:** HU07.

### RF08 — Gestionar establecimientos turísticos

El sistema deberá permitir al administrador registrar y modificar la información de los establecimientos turísticos.

**Historia relacionada:** HU08.

### RF09 — Gestionar usuarios

El sistema deberá permitir al administrador gestionar los usuarios de la plataforma conforme a los permisos y operaciones definidos para el sistema.

**Historia relacionada:** HU09.

### RF10 — Gestionar atractivos turísticos

El sistema deberá permitir al administrador registrar y modificar la información de los atractivos turísticos.

**Historia relacionada:** HU10.

### RF11 — Gestionar eventos y festividades

El sistema deberá permitir al administrador registrar y modificar la información de los eventos y festividades.

**Historia relacionada:** HU11.

### RF12 — Gestionar rutas turísticas

El sistema deberá permitir al administrador registrar y modificar la información de las rutas turísticas.

**Historia relacionada:** HU12.

## Consideraciones

Los requisitos deberán validarse con el alcance definitivo del proyecto. Las operaciones de eliminación, aprobación de publicaciones, autenticación y recuperación de contraseñas deberán documentarse si forman parte de las funcionalidades acordadas.
